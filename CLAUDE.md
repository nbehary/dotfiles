# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

Personal dotfiles (Arch Linux / Debian / macOS), centered on a heavily customized Neovim config for Kotlin/Java Android development. Active development happens on the `android_neovim2` branch; `main` is the PR target. There is no test suite — verify config changes by loading them in Neovim (`nvim --headless "+doautocmd VimEnter" "+lua ..." +qa` works for quick checks).

Note: `.github/copilot-instructions.md` is stale (describes the old macOS/Copilot setup); this file supersedes it.

## Plugin Management (vim.pack)

Plugins use Neovim's built-in `vim.pack`, vendored into `.config/nvim/pack/github/{start,opt}/` — that directory is **gitignored**. The source of truth for what's installed is `scripts/install-nvim-plugins.sh`.

To add a plugin:
1. Add an `install_plugin "owner/repo" "$START_DIR/name"` line to `scripts/install-nvim-plugins.sh` (use `$OPT_DIR` for `:packadd`-loaded plugins)
2. Run `bash scripts/install-nvim-plugins.sh` (clones/updates everything, compiles telescope-fzf-native and LuaSnip C modules)
3. Create `after/plugin/<name>.lua` with its setup

## Neovim Config Layout

- `init.lua` — options, core keymaps, autocommands, kanagawa colorscheme, and the `/tmp/nvim` server socket (used by MCP servers so Claude Code can drive the editor)
- `after/plugin/plugin-configs.lua` — most plugin setups, wrapped in `pcall` inside a **VimEnter autocmd** (`once = true`); configs there don't take effect until VimEnter fires
- `after/plugin/<name>.lua` — one file per plugin for the rest (telescope, treesitter, lsp-setup, linting-setup, claudecode, dap, android, …)
- `after/ftplugin/java.lua`, `kotlin.lua` — filetype-triggered LSP startup and settings
- `lua/` — supporting modules: `jdtls_start.lua`, `android/` (project config + task discovery), `claude_review.lua` (floating diff viewer for a PreToolUse hook)
- `bin/` — Android helper scripts on PATH: `android-run`, `android-debug-launch`, `android-logcat`, `android-kls-setup`

## LSP / Linting Architecture (the part that's easy to get wrong)

- **Java (jdtls):** started manually via `after/ftplugin/java.lua` + `lua/jdtls_start.lua` using nvim-jdtls. **Never add jdtls to `mason-lspconfig.setup()` handlers** — it's intentionally excluded.
- **Kotlin LSP (KLS):** installed via Homebrew, *not* Mason. The jar must be patched for AGP 9 (`scripts/setup-kotlin-lsp.sh`, idempotent; re-run with `--patch` after any `brew upgrade kotlin-language-server`). Each Android project additionally needs a `kls-classpath` script in its root, generated by `bin/android-kls-setup`. KLS needs the project built once (`./gradlew assembleDebug`) before it resolves classpaths.
- **Kotlin diagnostics:** come from **nvim-lint + ktlint** (`after/plugin/linting-setup.lua`), not from the LSP. ktlint is resolved from its Mason install path explicitly, runs with `--stdin`, and uses `--android` for Android projects.
- Mason auto-installs `ktlint`, `jdtls`, `stylua`, `java-debug-adapter`, `kotlin-debug-adapter` on first launch via mason-tool-installer.
- DAP/debugging is the known-broken area (connects rarely; work in progress — see `docs/DAP_GUIDE.md`).

## Claude Code Integration

- `after/plugin/claudecode.lua` — claudecode.nvim (same IDE protocol as the VS Code extension). `<leader>ai` toggles, `<leader>as` sends selection/adds file, `<leader>ay`/`<leader>an` accept/deny diffs.
- CodeCompanion chat (`<leader>cc`) is backed by Claude Code via the `claude_code` ACP adapter; requires `npm install -g @zed-industries/claude-agent-acp`.

## Conventions

- Leader key is `<Space>`; insert-mode escape is `jk`.
- The `<leader>a` prefix is crowded: Android maps own `aa ab ad ag al am ao ap at`, harpoon owns bare `<leader>a`, Claude Code uses `ai af ar aC as ay an`. Check for collisions before adding `<leader>a*` maps.
- Lua is formatted with **stylua** (`stylua <file>`); config at `.config/nvim/.stylua.toml` (160 cols, 2-space indent, single quotes, no call parens).
- When keymaps change, update `docs/cheat_sheet.html` (the keybinding reference) — this is maintained deliberately and has its own commits.
